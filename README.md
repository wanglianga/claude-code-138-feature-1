# 云川美术馆 · 团体参观预约 / 讲解设备借还 / 展厅分流调度台

面向美术馆工作人员的**团体参观全流程单页系统**：学校、企业、旅行社在线预约，馆方依据展厅容量、热门展品、讲解员排班、安检通道与临时闭展安排确认预约；到馆后完成人数核验、耳麦发放、讲解员派工与批次入场；讲解途中沿**同一条预约记录**处理拥堵、**团体迟到后的路线重排（缩短讲解/改自助参观/改签，联动耳麦借用时间与讲解员排班，并把释放讲解员派给后续等待团）**、儿童走散、设备损坏、讲解员替换、游客改道、展厅维护等事件并联动参观顺序、设备押金、讲解时长与后续团队入场；离馆核销设备与押金、记录满意度；投诉时可回放完整证据链（含迟到压缩依据），支撑大团规则、排班与限流优化。

技术栈：**Vue 3 + TypeScript + Pinia + Vue Router + Vite**，纯前端工程（无后端依赖，数据由 Pinia + localStorage 持久化模拟）。

## 一、本地启动

### 方式 A：Docker 一键启动（推荐）

```bash
docker compose up -d --build
# 打开 http://localhost:8080
```

停止：`docker compose down`。容器内为 nginx 托管构建产物，已配置 SPA 路由回退与健康检查。

### 方式 B：Node 本地开发

要求 Node.js ≥ 18。

```bash
npm install
npm run dev          # http://localhost:5173，热更新开发
npm run build        # vue-tsc 类型检查 + 生产构建到 dist/
npm run preview      # 本地预览生产构建（默认 http://localhost:4173）
```

> 如遇 npm 全局缓存权限问题，可使用项目内缓存：
> `npm_config_cache=./.npm-cache npm install`

### 测试账号 / 视角

本系统为**无登录内网工作台**（演示），无需密码。在左侧边栏可切换：

| 视角 | 说明 |
| --- | --- |
| 馆方工作人员（默认） | 默认操作人「前台主管 沈姐」，可在侧边栏改名；所有操作留痕均记录操作人 |
| 团体联系人 | 可访问「团体预约」提交申请、在「全部预约」查看状态 |

数据每日重置演示：点击侧边栏 **↺ 恢复演示数据** 可清空 localStorage 回到初始状态。

## 二、页面与业务链路

| 页面 | 对应需求 |
| --- | --- |
| 🏛 运营看板 `/board` | 各展厅实时容量（含散客占用录入）、讲解员排班/带团热力图、设备库存、满意度与投诉、拥堵改道事件统计，自动给出**大团规则/排班/限流优化建议**；另列出**讲解员未配齐的等待团队及当前可接续讲解员** |
| 📝 团体预约 `/book` | 采集团体类型、人数、年龄层、语言、无障碍路线、讲解主题、到馆时间、联系人、车辆停靠、耳麦借用；提交即按主题生成建议动线并自动避让闭展/无障碍不可达展厅 |
| 📋 全部预约 `/reservations` | 按状态筛选、搜索，展开查看路线、押金与操作记录 |
| ✅ 预约确认台 `/confirm` | **15 分钟容量栅格**叠加本团预测满载率、临时闭展校验、大团拆批建议；按语言/主题/排班/带团冲突匹配讲解员；按到馆时段计算安检通道排队；可驳回 |
| 🏷 到馆前台 `/front` | 到馆登记（自动判定早到/迟到）→ 核验人数（差异提示）→ 从设备间发放耳麦并收押金 → 讲解员就位、批次安检入馆；**迟到 ≥20 分钟可直接在此启动路线重排** |
| 🔀 途中分流调度 `/dispatch` | 七类现场事件：展厅拥堵、团体迟到/等待、儿童走散、耳麦损坏换机、讲解员替换、游客改道、展厅临时维护；**智能改道建议**（同主题/儿童友好/无障碍/相邻/满载率/热门与禁拍综合评分）+ **对后续团队入场的容量冲突预警**；改道自动顺延路线与讲解时长 |
| ⏱ **团体迟到路线重排**（`/front`、`/dispatch` 内） | 学校团迟到后，依据**剩余讲解时长、展厅当前拥堵、下一团到馆时间**生成 **①缩短讲解路线 ②改为自助参观 ③改签其他时段** 三方案；联系人确认后自动调整耳麦借用时间与讲解员排班，释放的讲解员派给后续等待团队；自助参观推送电子导览与集合点 |
| 🎧 离馆核销 `/checkout` | 逐台核对耳麦完好/损坏/遗失，押金按损坏 ¥50、遗失 ¥200 自动结算；满意度评分后结束预约 |
| 🔎 投诉与追溯 `/trace` | 一张档案展示：预约/实际到馆时间、人数差异、计划/实际讲解时长、**迟到重排的压缩依据与各厅处置明细**、分流决策、讲解员派工变更、展厅容量回放、设备借还（含调整后的应还截止）与押金流水、完整操作时间线；投诉涉及讲解缩水时自动关联压缩依据；可登记投诉并保存馆方答复 |

路线调整时，每个展厅卡片都明确标注：**🧒 儿童友好、♿ 无障碍可达、🤫 需保持安静、📷 禁止拍照、🔥 热门展品、🛠 临时维护、实时满载率**，兼顾馆内安静观展与团队体验。

```
│  │                       # 智能改道评分、下游团队影响、讲解时长，
│  │                       # 以及团体迟到：讲解员截止/缩短/自助/改签/释放再派工
│  └─ schedule.spec.ts
├─ stores/
│  ├─ museum.ts            # 展厅/讲解员/设备池/实时维护/散客占用/馆内时钟

│  └─ lifecycle.spec.ts

```

### 关键业务规则

- 容量：展厅以 15 分钟为栅格汇总在馆团队人数 + 人工录入散客；≥85% 预警、≥100% 启动分流。
- 大团：≥35 人提示拆分，每批 ≤25 人、批间隔 ≥5 分钟。
- 无障碍：预约与路线生成自动剔除不可达展厅（四号厅），安检优先无障碍通道。
- 闭展：展厅静态维护时段与临时维护统一生效；确认时能在闭展后补看则顺延，否则标记跳过。
- 设备：耳麦押金 ¥200/台；途中换机不重复收押金，旧机损坏挂账；离馆统一结算（损坏 ¥50、遗失 ¥200）。
- **团体迟到路线重排**：讲解员最迟离场 = 下一团（含未配齐、拟由其接续的等待团）首站开讲前 10 分钟交接 与 当班结束 取早；三方案——缩短（按拥堵/主题优先级放弃展厅、按剩余预算压缩单厅并保证不晚于截止）、自助（站点转自助、推送电子导览 CH-08 与一层前厅集合点）、改签（检索讲解员/容量/闭展均满足的时段，优先非原讲解员）；联系人确认后，耳麦应还截止随新结束时间调整，讲解员排班自动更新，释放时段派给最早可接续的等待团；压缩依据逐厅留痕，投诉涉及讲解缩水时直接回放。
- 留痕：每一次确认、到馆、人数、设备、派工/换岗/释放、分流、维护、迟到重排、押金、满意度、投诉都写入同一预约时间线，投诉追溯直接回放，不依赖人工回忆。
